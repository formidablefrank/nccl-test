# nccl-test

Small MPI + NCCL test application for Leonardo. The program initializes MPI, chooses one GPU per rank, creates an NCCL communicator, and runs a single `ncclAllReduce` to verify multi-node, multi-GPU communication.

## How it works

The execution flow is:

1. MPI starts the job and discovers `rank` and `world size`.
2. Each rank computes a host hash from the hostname plus the machine boot ID to infer its local rank on the node.
3. The local rank is used to select a GPU with `localRank % deviceCount`.
4. Rank 0 generates an NCCL unique ID and broadcasts it to all ranks.
5. Every rank allocates CUDA buffers, initializes NCCL, and launches one `ncclAllReduce` on a CUDA stream.
6. The stream is synchronized, resources are released, and MPI finalizes.

The current source uses a default message size of `32 * 1024 * 1024` floats, but you can override it from the command line.

## Tech stack

## Folder structure

- `allreduce.c` - main MPI/NCCL/CUDA all-reduce program
- `allreduce.x` - compiled executable
- `spack.yaml` - Spack environment pinned for Leonardo CUDA 12.2 and A100 (`cuda_arch=80`)
- `source-build-env/spack.yaml` - alternate Spack environment that keeps `cuda@12.2` external and source-builds the requested HPC packages
- `hpcx-only-external-env/spack.yaml` - alternate Spack environment that keeps `hpcx-mpi@2.25.1` as the only explicit external package
- `hpcx-only-env.sh` - helper that exposes the `hpcx-only-external-env` toolchain to the shell
- `spack-env.sh` - helper that loads the site modules and activates the local Spack environment
- `build-source-env.sh` - concretizes and installs the alternate source-build environment
- `build-hpcx-only-env.sh` - concretizes and installs the HPC-X-only-external environment
- `batch-hpcx-only-env.sh` - Slurm script that builds and runs `allreduce.c` with the HPC-X-only-external environment
- `build-spack.sh` - concretizes, installs, and builds `allreduce.x`
- `batch-spack.sh` - Slurm batch script that rebuilds and runs `allreduce.x` with HPC-X MPI
- `cuda_aware_bcast_pnetcdf.c` - CUDA-aware MPI broadcast example with parallel NetCDF output
- `build-cuda-aware-bcast.sh` - builds the CUDA-aware MPI + PnetCDF example
- `batch-cuda-aware-bcast.sh` - Slurm script for the CUDA-aware MPI + PnetCDF example
- `nccl.sh` - module setup and environment variables for NCCL/CUDA/MPI
- `binder.sh` - rank-to-GPU and rank-to-network-device binding helper
- `batch.sh` - Slurm batch script for Leonardo
- `topo_leo.xml` - NCCL topology dump generated by the job
- `logs/` - Slurm stdout/stderr and NCCL debug logs

## Spack environment

The new environment is intended for Leonardo with:

- GPU: `NVIDIA A100-SXM-64GB`
- driver: `535.274.02`
- CUDA runtime: `12.2`

`spack.yaml` pins the stack to the versions that match Leonardo's current CUDA 12.2 software stack:

- `gcc@12.2.0`
- `nvhpc@25.11`
- `hpcx-mpi@2.25.1`
- `nccl@2.22.3-1`
- `cudnn@8.9.7.29-12`
- `hdf5@1.14.3 +mpi +fortran +hl`
- `parallel-netcdf@1.12.3 +cxx +fortran`

The NCCL spec is constrained with `cuda_arch=80`, which matches A100.

## Build

Install the environment and build the test binary with:

```bash
./build-spack.sh
```

This does three things:

- loads `spack/0.22-06`
- concretizes and installs the local `spack.yaml`
  - compiles `allreduce.c` into `allreduce.x`

## Alternate Source-Build Environment

There is a second environment in [source-build-env/spack.yaml](/leonardo_scratch/large/userexternal/jrayo000/nccl-test/source-build-env/spack.yaml:1) for a "build it yourself" stack where `cuda@12.2` is the only explicit external package in the environment file.

It installs these requested top-level packages as source-built roots:

- `nvhpc@25.11 +mpi +blas +lapack`
- `openblas@0.3.26`
- `openmpi@4.1.6 +cuda +legacylaunchers`
- `nccl@2.22.3-1 +cuda cuda_arch=80`
- `cudnn@8.9.7.29-12`
- `hdf5@1.14.3 +mpi +fortran +hl`
- `parallel-netcdf@1.12.3 +cxx +fortran`

Build that environment with:

```bash
./build-source-env.sh
```

This environment concretizes on Leonardo. Because the site Spack config injects cluster integration defaults for Open MPI, some low-level transitive dependencies such as `glibc`, `slurm`, `pmix`, `ucx`, `ucc`, `hcoll`, `knem`, and `lustre` still resolve as site-managed externals during concretization. The requested top-level HPC packages above are configured to build from source.

Also note that this is a single-pass environment: `nvhpc` itself is built from source, but the other roots concretize with `gcc@12.2.0` unless you do a second bootstrap stage and re-register the freshly installed NVHPC compiler with `spack compiler find`.

## HPC-X-Only External Environment

There is a separate environment in [hpcx-only-external-env/spack.yaml](/leonardo_scratch/large/userexternal/jrayo000/nccl-test/hpcx-only-external-env/spack.yaml:1) where `hpcx-mpi@2.25.1` is the only explicit external package in the environment file.

Build it with:

```bash
./build-hpcx-only-env.sh
```

Pinned versions in that environment are:

- `cuda@12.2.2`
- `nvhpc@25.11 +mpi`
- `nccl@2.22.3-1 +cuda cuda_arch=80`
- `cudnn@9.2.0.82-12`
- `hdf5@1.14.3 +mpi +fortran +hl`
- `parallel-netcdf@1.12.3 +cxx +fortran`
- `hpcx-mpi@2.25.1` as the MPI provider external

`cuda@12.2.2` is used here because it is the newest CUDA release in the `spack/0.22-06` package set that matches the Leonardo `535.*` driver line. This environment concretizes successfully and writes [hpcx-only-external-env/spack.lock](/leonardo_scratch/large/userexternal/jrayo000/nccl-test/hpcx-only-external-env/spack.lock:1).

Run `allreduce.c` with this environment using:

```bash
sbatch batch-hpcx-only-env.sh
```

If you want the steps separately:

```bash
module load spack/0.22-06
spack env activate -d .
spack concretize -f
spack install --fail-fast
source ./spack-env.sh
nvcc -O2 allreduce.c -o allreduce.x \
  -I"${HPCX_MPI_HOME}/include" \
  -I"${NCCL_HOME}/include" \
  -L"${HPCX_MPI_HOME}/lib" \
  -L"${NCCL_HOME}/lib" \
  -lmpi -lnccl
```

## Run on Leonardo

The new Slurm script is set up for a 4-node, 16-rank run with 4 GPUs per node. Submit it with:

```bash
sbatch batch-spack.sh
```

`batch-spack.sh` does the following:

- requests 4 nodes
- launches 4 MPI tasks per node
- requests 4 GPUs per node
- loads the Spack-backed runtime environment
- rebuilds `allreduce.x` with the active CUDA, NCCL, and HPC-X headers/libraries
- sets NCCL debug output and topology dump paths
- starts the job with:

```bash
mpirun -np 16 ./binder.sh ./allreduce.x 50000000
```

The final argument is the message size in floats. If you omit it, `allreduce.c` uses its built-in default.

## Scripts

### `nccl.sh`

Loads the Leonardo module stack and exports the include and library paths for NCCL.

### `binder.sh`

Maps each MPI rank to a specific network device and CUDA device:

- rank 0 -> `mlx5_0:1`, GPU 0
- rank 1 -> `mlx5_1:1`, GPU 1
- rank 2 -> `mlx5_2:1`, GPU 2
- rank 3 -> `mlx5_3:1`, GPU 3

It then launches the wrapped command.

### `batch.sh`

Contains the Slurm directives and the actual launch command used on Leonardo. It also enables NCCL debug logging and writes a topology dump to `topo_leo.xml`.

### `spack-env.sh`

Loads the Leonardo `spack/0.22-06` module, activates the local environment, and exposes CUDA, NCCL, cuDNN, and HPC-X MPI to the shell.

### `build-spack.sh`

Builds the local Spack environment and compiles `allreduce.x`.

### `batch-spack.sh`

Slurm job script that sources `spack-env.sh`, rebuilds `allreduce.x`, and launches it with `mpirun`.

### `cuda_aware_bcast_pnetcdf.c`

Uses a device buffer with CUDA-aware MPI to broadcast an integer from rank 0, then writes one copy of that value per rank into a parallel NetCDF file with PnetCDF.

Build it with:

```bash
./build-cuda-aware-bcast.sh
```

Run it with:

```bash
sbatch batch-cuda-aware-bcast.sh
```

The batch script disables the HPC-X `coll_ucc` collective component for this example because `MPI_Bcast` on a device pointer was crashing in `mca_coll_ucc` on this Leonardo stack.

## Output

Successful runs print one line per MPI rank:

```text
[MPI Rank <rank>] Success
```

Slurm stdout/stderr and NCCL logs are written under `logs/`.

## Notes

- `batch.sh` contains Leonardo-specific account, partition, and QoS values. Update them if you run under a different project.
- `batch-spack.sh` contains Leonardo-specific account, partition, and QoS values. Update them if you run under a different project.
- If you want to benchmark different message sizes, pass a different final argument to `allreduce.x` in `batch-spack.sh`.
- `topo_leo.xml` is regenerated by the job when `NCCL_TOPO_DUMP_FILE` is set.
- The environment uses Leonardo's installed `cudnn@8.9.7.29-12` rather than the newer Spack-preferred `cudnn@9.2.0.82-12`, because the installed CUDA 12.2 module stack is already validated with the former.
